## Product and integration

- AI aim is the independent fourth switch (`AI瞄准`), off on every process start, activated by RMB hold. Enabling it starts the existing weapon/equipment/stance recognition chain; no duplicate weapon recognizer or automatic firing is connected.
- User-customizable default keys: weapon recognition F1, distance F2, recoil F3, AI F4, large-map measurement F5. Existing valid bindings win. A missing action gets its default only if free; otherwise remain unbound and show `未设置`. Conflict checks normalize case/brackets/whitespace.
- Reuse `WeaponDetector`, `EquipmentDetector`, `GestureIdentifier`, `HotkeyManager`, `StatusHud`, `Config/ResourcePaths`, and shared `MouseMotionDispatcher`. Neutral `EquipmentSelection` owns shared slot selection, not the AI adapter.
- M762/RPD are native full-auto with `auto_fire:false` (that field means generated repeated taps). RPD uses the M249 recoil curve as a tunable baseline and has weapon/equipment templates.
- HUD label is exactly `自瞄`: red off, yellow enabled/no recognized weapon, green enabled/recognized weapon. This is recognition, not output eligibility. Initialization/runtime errors use temporary messages.
- MK47 was recognized; the user's 6x triggered `activation.disable_variable_high_zoom=true`, which clears eligible weapon for 6/8/multiple scopes and formerly produced misleading waiting-weapon text. Templates/name mapping exist. The gate is configurable; its default remains true. Scope context uses fixed 6x/8x, not reduced zoom selected by the user.
- AI gates require enabled module, supported recognized context, RMB, PUBG foreground, fresh frame, and no known blocking UI. Escape/menu state fails closed and requires repeated hidden-cursor confirmation before resuming.
- Runtime requires packaged x64 ONNX Runtime/DirectML/model, validating bounded manifest entries, PE architecture, sizes, and SHA-256 before load. Production has no silent CPU fallback; CPU is explicit smoke-test-only.

## Settings and tuning

- `config/ai_aim_settings.json` remains schema version 1, backward compatible with missing optional keys. `AiAimSettings` owns parsing/serialization and uses module sanitization; ordinary `Config::save` never rewrites AI settings.
- Settings button `AI 瞄准参数设置` opens four tabs: 目标识别、跟随/灵敏度、开火控制、移动预测. There are 63 controls, driven by reusable `ui/AiAimParameterCatalog`. Every control has a “说明” button; click/focus shows persistent right-side help with default, UI range, purpose, adjustment effects, conditions/caveats, and JSON path.
- Defaults come from serialized module defaults, not another catalog copy. No algorithms or existing parameter defaults were changed by the advanced editor work. Hidden legacy fields remain preserved, not mislabeled as effective controls.
- Newly exposed/mapped controls include class-location aim height, tracking IoU/lost frames, X/Y P/I/D, debounce, firing Y-pause, class/scope/distance/lean/SMG fire offsets, effective normal prediction factor/deadzone, lead smoothing/step/Y/hold/jump reset. Existing detector, sensitivity, scope, and prediction controls remain.
- Draft/reset/reload do not apply runtime changes. `保存并应用` first atomically saves and then applies the exact committed validated snapshot, without rereading a potentially externally changed file. No application restart is needed. Hidden fields/precision/partial arrays remain preserved; head/body selection is validated. Config document+existence snapshots reject stale saves after external edit/create/delete. Failed persistence never applies; failed runtime application is reported and can be retried using the updated save baseline.
- Live settings reuse `AimModule::updateConfig` via `AiAimCoordinator::updateConfiguration`, fencing motion, resetting tracking, and updating the sink's frame lifetime. Keep enabled/paused state unchanged. Replace the captured factory for future enables; saving during initialization cancels the old attempt with its own stop token/generation. Hidden device changes asynchronously recreate only the AI runtime. App serializes settings/context/activation using its recursive AI status lock, pauses output until policy and algorithm agree, and advances the session to reject old HUD/error samples.
- `display.target_boxes` is a host-only setting, default false, exposed as `显示目标淡框` on the target tab. Require both main display and AI switches plus active AI detection/hold/foreground/menu gates. Reuse immutable `AimSnapshot::detection_frame` and the existing StatusHud/OverlayWindow, not another recognizer or overlay thread. Frames carry real ROI/desktop coordinates; `AiAimTargetOverlay` clips to ROI/selected monitor and rejects malformed, future, or stale frames (at most 150ms lifetime). Existing monitor refreshes at 50ms.
- Target outlines are 1px, alpha 85, red -> yellow -> green as confidence rises, with no confidence numbers/text. Render detected head/body boxes, not an enemy/team classification; model cannot distinguish teammates. Clear snapshots on config/reset/unsafe activation/context/error/stop; publication checks safety/config generations so old inference cannot restore cleared boxes. All visual settings remain independent of recoil and aiming math.
- HUD `当前` line ends with lowercase `fps: xx.x` after optional peek direction, with no Hz suffix (user's requested label). It measures actual AI valid-frame completions, including empty detections, not game FPS, weapon recognition, capture-sequence gaps, configured FPS or 20Hz host polls. Module-local `detail::RecognitionFrequency` uses allocation-free 500ms averages and 1s no-frame expiry. Reset on disable/pause/config/tracking/error/stop; coordinator masks invalid sessions. `AimSnapshot::recognition_hz` shares the monitor/`StatusHud::setAiSnapshot` publication with boxes. Display/box switches do not affect the rate; render on text/box changes. Warmup takes about 500ms; aim/recoil math is unchanged.
- Shared themed popup wheel behavior: QAbstractSpinBox/QSlider/QComboBox never change values by wheel, even focused. Forward the wheel with pixel/angle/phase/device data to the nearest QAbstractScrollArea viewport; scrollbar/dropdown lists, keyboard, arrows, and drag remain functional. ChildAdded/ChildPolished covers late nested controls. Merely ignoring the event did not scroll correctly; explicit forwarding is regression-tested.
- AI and recoil intentionally add output in one dispatcher. Imported defaults include firing body offset 120 plus Y tracking, potentially overcorrecting or moving the aim point outside range. New “开火时暂停 AI 纵向跟随” only zeros AI Y during firing; it neither enables recoil nor removes fire offsets from range checks. Offset controls allow manual comparison; no automatic coordination/tuning or recoil-curve changes were made.
- Speed facts: max_pixels only clamps motion; PID gain is global_scale * pow(clamp(base/current,0.3,3),1.36) / clamp(scope_zoom,1,10). Existing acquisition gain ramps through .45/.65/.82/1 over tracked frames. P defaults X=.881/Y=.456 are adjustable. I is legacy per-frame recurrence, not time integration; D lacks dt normalization. Global scale also changes FOV/range. UI P/D ranges 0–10, I 0–.95; untouched imported values retain precision.
- Effective prediction uses normal_predict_factor/deadzone; legacy predict_factor/deadzone/location remain hidden. Fire offsets apply to non-DMR and share 3/6 and 4/8 scope multipliers. Positive offsets move down. Distance scaling uses detected box size, not true measured distance. Y-prediction=0 does not disable normal Y tracking.
- Diagnose sustained drift by separating recoil-only from combined output before editing curves. Disk switch state is not proof of live state. Actual aim feel and reduced-zoom behavior remain live-session checks.
